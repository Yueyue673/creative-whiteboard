# 从完整创作流程评审白板

目标是让人更容易开始、持续创作和接着上次的工作。功能数量、提交次数、通过测试或视觉变化本身，都不能证明产品更好用。

## 用原则提出问题

下面是把公开设计原则用于白板的评审方法，不是原作者的评审意见、授权或质量背书。

| 参考 | 在白板中要问的问题 |
| --- | --- |
| [Don Norman：执行与理解之间的鸿沟](https://www.nngroup.com/articles/two-ux-gulfs-evaluation-execution/) | 用户知道下一步怎么做吗？操作之后，能看懂发生了什么、影响哪个对象吗？是否被迫理解内部的目录、窗口或异步状态？ |
| [Dieter Rams：好的设计原则](https://www.vitsoe.com/us/about/good-design) | 层级、比例、排版和细节是否帮助使用？哪些东西可以删除？新功能是否增加了理解和维护的负担？ |
| [Bret Victor：Learnable Programming](https://worrydream.com/LearnableProgramming/) | 能否把状态、过程和结果直接呈现在操作对象旁，让人边做边理解，而不是记住术语、反复打开面板或猜测后台进度？ |

工程评审同时追问：问题属于交互模型、状态归属、异步时序、数据协议还是布局？同一个机制是否还影响其他入口？不要给每个症状分别贴一个提示。

## 先走完任务，再决定做什么

仅使用独立合成内容。交替检查首次使用者、长期创作者、小窗口使用者和出错后恢复者的完整任务，例如：

- 从空工作区开始，把资料放到指定位置，写便签，整理关系，保存后继续。
- 在长文、内容库和左右分栏之间反复切换，保持原文字、选区、视角和操作目标。
- 从另一设备接续已保存工作，在断线、保存冲突或权限变化时知道当前状态并保住输入。
- 移动、删除或关闭后反悔，回到正确内容并继续创作。

任务之间轮换，优先补长期未审视的路径。已有检查通过只说明当时的具体行为；没有新变化或新疑点，不反复跑它们。若评审一直只发现边角排版，换一个任务或用户视角，检查现有结构是否本身增加了负担。

观察真实操作中的停顿、回找、重复点击、目标猜测、意外跳转、焦点丢失和等待。记录宽屏与窄屏整体画面，不能只截局部按钮。对长时间使用的判断须注明实际观察时长，短测不能代表整天使用。

## 把症状还原成原因

对重要发现记录以下内容，不要求每轮凑出固定数量：

1. 用户本来想完成什么，在哪一步停住。
2. 实际步骤、画面或性能记录；哪些只是待验证的推测。
3. 根因假设、受影响入口，以及什么证据会推翻这个判断。
4. 按数据风险、任务阻断程度、发生频率和影响范围选择优先级。
5. 可观察的改善目标，例如少一次来回切换、无需猜测目标、等待期间能继续编辑，或可定位的本机处理耗时下降。

数据安全和核心流程故障优先。普通体验问题不能仅按“容易修”排序，也不能因为自动测试通过就判为没有问题。

## 给结构性改进留空间

对影响明显的问题，比较一个沿用现有流程的方案与一个改变流程的方案。后者可以重组信息层级、合并步骤、直接操作对象、使用空间或时间表达；不局限于增加按钮、换色、圆角和提示。

先用同一任务比较它们的操作成本、理解成本和恢复方式。低风险原型直接放进原产品的独立测试环境，保留退出、撤销和还原。实验范围应足以验证想法，但不接触正式创作数据。原型更复杂或收益不成立就撤掉，保留判断依据；不为证明“有创新”强行上线。

例如，拖入后没有动静，可能是插入过程和目标不可见。比较角落通知与落点占位的完整接续，比反复修改“请稍候”更接近问题。这个例子说明推理方法，不要求重新实现已完成的插入反馈。

## 用结果验收

变更前写清任务、预期收益和保留条件。变更后在原界面真实操作，检查收益是否发生，再做受影响回归。性能区分网络、解码、布局、绘制和保存，记录样本与设备条件，不从减少 DOM 次数直接推导用户更快。

文字、媒体、手动尺寸、固定账号和工作区、选区、视角与撤销重做按场景核对。测试失败先查明产品、夹具或时序原因，不能放宽原行为断言来取得绿色结果。

已经验证的问题、未验证的假设、实施结果和下一步分别记录。若没有足够证据支持改动，就继续调查或保留现状，不制造提交。

## 发布仍以现有创作为先

新程序与现有数据分开处理。已有账号、工作区、素材和签名密钥不重新初始化；兼容程序回退不能用旧备份覆盖后来创作。发布前验证匹配版本的完整备份与恢复入口，失败就不切换。恢复演练使用独立空目录，不在正式数据上试验。

桌面与托管服务沿用同一原工作台，但账号、数据位置、可用功能和已验收设备应分别说明。已打开的创作窗口不强制刷新。浏览器本地外观偏好不能写成云端同步，周期接收不能写成逐字实时协作。

开发者可用这份方法评审；具体部署的运维保障、权限和发布条件仍以其经过验证的操作流程为准。本文件本身不安装定时备份或提供任何数据保障认证。
