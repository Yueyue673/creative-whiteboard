# 内容库短暂读取占用时，继续完成同一次保存

Windows 中已有目录正在被短暂读取时，系统可能暂时拒绝原子的文件替换。内容库保存仍先准备完整的新目录，再替换原文件；遇到这两类 Windows 临时访问错误时，会在同一次保存内短暂等待并重试，等待合计最多300毫秒。正常写入不会增加等待，也不会自动再次提交保存请求。

每次等待后都重新核对原目录。若等待期间已有新的目录内容，停止本次替换并提示刷新，保留后来版本与完整的待写文件。持续无法替换时，停止并提示稍后再保存；已有目录和待写内容保留。其他文件错误直接报告，不转为反复重试。原有版本校验、历史恢复点、资源身份和附件保存路径继续使用。

本机核对包括受控错误边界，以及真实 Windows 普通读取句柄下的短暂占用、持续失败后明确重试、等待期间后来版本保护。使用原 HTTP 保存入口与临时合成目录；没有读取作者目录或正式恢复包。这项改动没有声称提供断电耐久性或跨进程事务，也没有认定此前未完整记录的那次400响应具有相同原因。

新增核对由原 Check 的 `python -m unittest discover -s tests -v` 自动发现，原矩阵涵盖 Ubuntu/Windows 和 Python3.10/3.13。真实 Windows 句柄核对在 Windows 执行，其他平台明确跳过这三项；受控边界核对在两类平台执行。当前完成的是本机源码与隔离核对，准确当前提交CI、服务器QA、网站更新、私人安装及作者实际使用仍待对应阶段。
